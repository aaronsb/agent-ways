# A Figure in a Decision Record

A record carries a figure when it decides something a reader sees or that a picture explains: layout, appearance, geometry, timing, flow or state. It also carries one when the operator should steer on a picture before implementation starts.

## Making the figure

- A picture that communicates beats none. A rough hand drawing counts.
- A figure generated by code in the project's visual language is better. The project keeps a small shared vocabulary in one module it owns: a palette legible in light and dark themes, shapes, line styles, a legend, and type sizes. Every figure draws from that module, so the project's figures read alike.
- Mermaid suits structure, flow and state where it is enough. The mermaid way covers its syntax and its styling for both themes.

## The figure is frozen with the record

A record's figure is a point in time. It belongs to the record and freezes with it. The operator put it this way: "the diagram is frozen because it's a point in time", and "an ADR as written was as it was at the time, and there's no concievable way to go back and reauthor as things change. ADR is a type of ledger and a record of what was decided."

- After acceptance the figure is never redrawn. A changed design is a new record with its own figure.
- The figure prints no status and no build state. Either one goes stale.
- A figure of the system as it is now belongs in living docs, such as a guide, where a drift check against source applies.

## Placement

- Save the figure as `figures/ADR-NNN-<slug>.svg` in the record's folder. Commit it in the same PR as the record.
- Embed it beside the decision item it draws. Introduce it with a sentence that says what it shows. Give it alt text that states its content.
- When the figure is how the decision is seen, an `observable` entry may name it.

## The generator

- Commit the generator beside the figure.
- The generator is deterministic: the same inputs give the same bytes. It reads no clock and no randomness, and it does not measure fonts.
- Each value the record introduces lives in one place, for example a values block in the record that the generator reads.
- While the record is proposed, a check regenerates the figure and fails on a mismatch. The same check compares the figure's values with the record's.
- At acceptance the check stops redrawing that figure.
- Prove the check once with a planted stale figure: copy the figure to a backup, edit the figure, run the check and see it fail, move the backup back, and touch the figure.

## Drafting and showing

- Draft the record and its figure together. When an operator answer changes what the figure draws, redraw the figure in the same round.
- Before asking the probes, render the SVG to a PNG in the session scratchpad, for example with `rsvg-convert`, and send the PNG to the operator.
- A probe about appearance names the figure.

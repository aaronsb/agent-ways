# ways-theme

Claude Code follows the active agent-ways theme (ADR-514). The theme is chosen in one place, `theme.active` in ways settings, and the mod adds no setting of its own.

`ways manage mod install ways-theme --commit`, or the mod tab in `ways settings`, installs it. `mods.ways-theme.install` defaults to false.

## The theme file

Claude Code keeps one custom theme for agent-ways, `custom:ways`, in `${CLAUDE_CONFIG_DIR:-~/.claude}/themes/ways.json`.

- **Selection.** Installing the mod claims `"theme": "custom:ways"` in the target's settings.json, through the settings merge that `ways manage repair --commit` and the mod manager run, and records the theme it replaced in the merge base. Uninstalling restores that theme, or removes the key when there was none, and removes `themes/ways.json`. A theme the person picks after the claim is kept through both. `ways manage repair --what-if` names the change. The mod selects nothing itself, because `$.config.set` refuses a custom theme in Claude Code 2.1.312 (anthropics/claude-code#105739).
- **Colours.** At an interactive session's start the mod reads `ways settings get theme.active` and rewrites `ways.json` when its content changed: `ways settings theme export <name> --claude-code` for a theme, Claude Code's own dark for `terminal`. It does the same mid-session whenever the export that configures the drawing (below) changes, so a switch of theme or an edit to its colours reaches `ways.json` within 5 seconds, and a rewrite that failed is tried again on each later read. Claude Code watches its themes folder, so the change applies live.

Claude Code draws on the terminal's own background, so the exporter lifts every text colour to its contrast floor on the theme's bg and on a band of common terminal grounds of the theme's kind. A theme file's `[target.claude-code]` table pins any Claude Code colour token over the mapping.

## Frames

On the terminal, under an agent-ways theme, each reply sits inside a round border on the theme's ground, and each tool call and tool group inside a round border, wrapped around Claude Code's own drawing. A dark theme pairs with Claude Code's dark base and a dark terminal, a light theme with the light base and a light terminal, whose default foreground is dark; Claude Code draws a reply's body in that foreground. A light theme in a dark terminal is a mismatched setup, and its replies read poorly. The colours are Claude Code theme keys (`userMessageBackground`, `claude`, `suggestion`, `error`), which hold the agent-ways theme's colours only while Claude Code's selected theme is `custom:ways`. So the frames draw only then: under another theme picked in `/theme` or `/config`, they and the person's message box step aside for Claude Code's own drawing, and picking `custom:ways` again brings them back with no restart. The mod reads the selection from the `theme` row of `/config` at a session's start, when the row changes, and every 5 seconds, which catches a settings.json written by `ways manage repair`; a row it cannot read draws no frame. Claude Code draws its own row, unframed, in the ctrl+o transcript, which the mod reads from the line that closes a turn, for a tool row expanded on its own, for a reply longer than 20,000 characters, for a block that does not open a reply, and on every surface other than the terminal. Under `verbose` Claude Code reports every row expanded, the main view included, so the mod frames rows as it does with `verbose` off, and the ctrl+o transcript, which then looks the same to the mod, is framed too. A frame costs four columns of width.

## The transcript drawing

The mod also redraws the transcript, headless, with the renderer of [skins](https://github.com/hellosverre/claude-skins) by hellosverre (MIT, ported from commit 985ad63; the licence is at `hooks/skins/LICENSE`). On the terminal it draws tool rows on a rail with their fold, open and copy controls, shell output as a card, tables, highlighted code, diff fences, math, Mermaid charts (laid out by the vendored beautiful-mermaid, MIT), alerts and task lists, the spinner with the theme's words, the turn footer, the usage band above the prompt, and the person's message in a box. Skins' `/skin` command, its settings pane, its design tool and skill, its themes, its settings store, its update check and its Compact button are not part of the port. Nothing in Claude Code configures it.

One call configures it: `ways settings theme export --mod`, at an interactive session's start and every 5 seconds after, bounded at 1.5 s. The export names the theme, its colour roles, its gradient, its spinner and footer words, and the `render` switches: `rail`, `tables` (`on`, `text`, `off`), `shimmer`, `charts`, `markdown`, `icons` (`unicode`, `ascii`), `frames`, `prompt_box` (`off`, `frame`, `gradient`), `copy`, `copy_style` (`verbose`, `compact`) and `paths` (`wrap`, `truncate`). A change in `ways settings` reaches an open session within 5 seconds, and an unchanged export redraws nothing. An export that fails, or that does not match the contract key for key, leaves the drawing as it was: Claude Code's own at a session's start, the last good look afterwards.

The skin's colours come from the theme's roles: `accent` for the person's marks and the rail, `body` for text, `muted` for secondary text, `ok`, `err` and `warn` for outcomes, `info` for reads, `hot` for writes, `warn` for shell runs, `alt` for searches, `accent_dim` for web calls, `muted` for MCP calls and `rule` for the rest. A table's header band and its zebra rows are steps from `bg` toward `subtle`. Under the `terminal` theme the drawing takes skins' own terminal look, the terminal's sixteen colours.

Each reply, tool row and tool group sits in one frame, the one described above, and `render.frames` switches them off. Whether a row is framed follows this export and Claude Code's selected theme: a theme with colours, not `terminal`, `frames` on, and `custom:ways` selected. The frame and the row inside it read the same look, so a theme switched mid-session reframes the rows already drawn, and a session whose export has not loaded draws no frame. A shell call's card is that call's frame, so its row goes unframed. A call whose row Claude Code draws empty (ToolSearch, SendUserFile, TodoWrite, AskUserQuestion, the plan-mode tools, SendUserMessage, ScheduleWakeup) gets no frame, nor does a group of only such calls; a SendUserFile that sends an image is framed at its result, the row that shows it. Inside a frame the rail draws no connector.

A picture another mod draws in a framed row, as the images mod does under a SendUserFile, a Read of an image, folded Reads or a reply that names an image file, sits inside the frame with its caption when that mod comes after ways-theme in the hook chain: the theme's row heads the frame, and a picture wider than the frame's room is narrowed to it, its height in proportion, since the theme cannot hand that mod a narrower width. The mod's caption still gives the scale it drew at, so after narrowing its percentage overstates the shown size by a few points. When that mod comes first, it draws under the frame. A reply holding a copy block keeps the picture under its framed pieces, unframed. ADR-517 brings the images mod into this repository, where it draws inside the frame and sizes itself to it.

On the terminal, the text in a reply that the person copies draws as a block of its own: its text with nothing else on its lines, the terminal wrapping it, and its copy control under it. A reply that holds one is framed in pieces, a frame around each run of prose and each block between the frames, so a selection over the block crosses no border or padding. There are four kinds:

- A `! <command>` suggestion, a shell command for the person to run from Claude Code's prompt: a line that starts with `! `, after any list marker, an inline code span whose content does, or a fence, with no language or a shell's, of one command that does. A `!` inside a sentence, `!=`, `!!` and an image stay prose.
- A slash command: a line that is only the command's name, such as `/clear`, or, with its arguments, an inline code span or a one-line fence with no language. The name is one Claude Code lists as a command the person can run, built-in, plugin or MCP, which the mod reads at the session's start and at each turn. A route such as `/health` stays prose, and so does a sentence or a list item that opens on a command name. Before the list is read, any name but a top-level directory such as `/tmp` or `/nix` counts.
- A fence's code, its language above it, each line highlighted with nothing beside it. A fence inside a list item loses the item's indentation, as CommonMark reads it, and its trailing blank lines. A Mermaid chart and a diff keep their drawing.
- An inline code span wider than 60% of its row, less an open list item's indentation, which leaves its sentence so it does not wrap inside the frame.

A copy goes through the terminal's clipboard tool or OSC 52 and toasts what it copied. On the terminal the copy controls draw only under Claude Code's fullscreen layout: on the main screen a row is printed into scrollback, where no control can be pressed. With `copy` off none draws. A press copies one form of a block:

- `markdown`, the block as written;
- `native`, its own form: a table as CSV with its header row, a code span in a cell kept as written; a fence's code as written; a suggestion as typed, `! ` or `/` included;
- `text`, the text as drawn, with no border glyph or padding: a table's header and rows, its columns padded and two spaces apart.

A block offers the forms whose copied text differs. A table offers up to three, and two where its CSV and its text are the same, as in a one-column table of plain cells; a fence offers `markdown` and `native`, and a suggestion or a wide span one copy. A diff fence adds `new only`, its code after the change. Each form is labelled by the format it copies, so `native` reads `csv` on a table and the fence's language on a fence, `python` or `sh`, or `code` where the fence names none. Under the reply, `Copy reply as: markdown · text` copies the reply as written or as its text. `copy_style` at `verbose`, the default, draws a table's control as `Copy as: markdown · csv · text`, each form a button of its own in the theme's accent and the lead muted; a block with one copy draws a bold `Copy` in the accent. At `compact` the control is a copy glyph and a glyph per format, a language taking the code glyph: Nerd Font glyphs under `icons: unicode` on the terminal (the copy, markdown, table, code, align-left and plus icons), `cp`, `md`, `csv`, `code`, `txt` and `new` under `icons: ascii` and on the desktop, whose buttons have no Nerd Font. In ASCII the reply's control opens on `reply`. A `·` separates the forms, a `|` under `icons: ascii`. One table in `hooks/skins/copy-rows.tsx`, `LABELS`, holds every word and glyph; `hooks/skins/commands.ts` holds the rules for what a block is.

Nothing folds. An opened tool row draws its whole answer, each long line wrapped, since the terminal prints a row into scrollback where no control can be pressed. A tool row's command, pattern or address draws whole and wraps, as does a shell card's `$ command` header; a command's later lines show as `…` on the row. The desktop's code, diff and terminal cards draw every line and wrap a long one. An answer or a card too big for one drawing keeps Claude Code's own drawing.

With `paths` at `wrap`, the default, a tool row's file path that does not fit beside the tool's name and its facts moves onto lines of its own under the name, aligned with it. It breaks after a `/`, and inside a segment only when the segment is wider than the line. Every character is drawn, in the row's colour, and each line links to the file where the row links it. `truncate` keeps the path on the tool's line and cuts it short with an ellipsis. The desktop draws the path on the tool's line either way.

The person's message, with `prompt_box` at `gradient`, sits on the theme's gradient in `body` text, mixed in OKLab. A message under 4 lines runs the gradient across each line, padding rows included; one of 4 lines or more runs it down the lines. A message with an image or a `[Pasted text #N]` placeholder, a row in the ctrl+o transcript (under `verbose`, as for the frames, no row counts as one), a view under 12 columns and the `terminal` theme take a plain outline instead, as does a message holding an emoji sequence (a joiner, a variation selector, a skin tone or a flag) where the engine cannot segment graphemes. Lines keep their indentation, and the box never splits a grapheme between two grounds. So does every message under a theme with no gradient: `ways` exports its `prompt_box` of `gradient` as `frame`. A message holding a control character is Claude Code's own, as is every message while another Claude Code theme than `custom:ways` is selected. Text pasted into the message draws, in the box and in the outline, as Claude Code shows it: the `<pasted_content>` wrapper is taken off, and a paste that spans lines sits on lines of its own. As in Claude Code, a typed line straight after a paste loses its leading whitespace. A paste that carried another paste's tags shows without those tag lines too, every other line of it as pasted, where Claude Code shows the tags escaped. A wrapper that is not one of this session's pastes and a tag closed under another id draw as typed. A tag left open draws as typed, and so does the rest of the message after it. A message with a paste is Claude Code's own when the mod cannot read the session id. With `copy` off, no copy control is drawn.

On the terminal, a message another party sent (a mod's delivery, another session's, a channel's, a task notification) has its wrapper blocks set apart where Claude Code draws it in full: in the ctrl+o transcript, under `verbose`, and under a speaker label whose body fits. A wrapper block is an opening tag of lowercase words joined by hyphens alone on its line, such as `<attend-peer-messages>`, and its closing tag alone on a later line. Its tags give way to a label in the theme's `muted` colour, the tag name with spaces for hyphens and any double-quoted attributes of the opening tag beside it, and its body is indented under the label. A block inside a block is indented again, to four levels. The text around the blocks, a tag with anything else on its line, a tag left open, a tag closed under another name and every tag inside a fenced code block draw as they came. The compact row is Claude Code's, or the drawing of the mod that sent the message, as is a message carrying an image, and the person's own message keeps its tags as typed. Like the person's message box, this needs an agent-ways theme with `custom:ways` selected, and a message holding a control character is Claude Code's own; `prompt_box: off` turns off the person's box alone, and the wrapper blocks draw whatever it says.

On the desktop, VS Code and mobile the rows skins draws there are its own (the desktop's cards), and the person's message, the frames and the gradient are Claude Code's own drawing.

## Failures

Each `ways` call is bounded at 1.5 s. A missing `ways`, a non-zero exit, output that does not parse, or a call past its bound leaves the file or the look as it was, and leaves one debug-log line. A headless (`-p`) session changes nothing.

A theme's gradient, border and rule glyphs, marks, presence and event glyphs and ornament do not reach Claude Code's chrome.

## Versions

The plugin carries the `ways` version, since it calls `ways settings` verbs: `scripts/release.sh bump ways` moves both, and `make test-plugins` checks them.
